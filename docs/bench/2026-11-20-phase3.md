# Bench note, Phase 3

2026-11-20, Windows 11, Intel Core Ultra 7 255H, MSVC (Visual Studio 18), the suites in Debug and
`likyu_bench` in Release. What Phase 3 measured, beside the rows it turned green. The figures
behind each threshold are printed by the tests that hold them (`MESSAGE` lines in
`tests/dsp/DetectorTests.cpp`, `DynamicsTests.cpp`, `MovementTests.cpp`).

- **Float is enough for the detectors.** At the one place Phase 2 found float wanting (20 Hz, Q 40,
  192 kHz), the float detector still reads the level within 0.003 dB. A detector's Q being slightly
  off changes what it hears a little, not what it reads of a tone at its centre.
- **The low-pass follower ripples on content far below it**, as the author's decision foresaw.

## The plugin (3b to 3d)

- **The key is the input undelayed.** A dynamic bell keyed by a burst: with a 3 ms lookahead the
  burst's first 2 ms come out at −16.6 dB, against −8.0 dB without. The rest of the "lookahead
  effect" row, Transient, is Phase 4's.
- **Blocks of 6000 samples**, 94 times the size announced to `prepareToPlay`, give what blocks of
  64 give, bit for bit, through the 256-sample chunks.
- **Meter snapshot:** a writer thread publishing 200,000 times and a reader polling, some 150,000
  reads per run: never torn, never backwards.

## Timing (Release)

`likyu_bench time`, the chain's process call alone, 10 s of audio after 200 blocks of warm-up,
96 kHz, blocks of 64 (a period of 666.7 µs), stereo, float buffers unless said. Median, as a share
of one core. Beside it, Phase 2's figure, measured again the same day from `470d098`.

| Scenario | Phase 3 | Phase 2 |
| --- | --- | --- |
| 8 static bands | 0.39 % | 0.36 % |
| 8 static bands, double buffers | 0.41 % | 0.45 % (bench note of Phase 2) |
| 8 bands, every ramp always running | 0.99 % | 0.88 % |
| **8 dynamic bands keyed by a stereo sidechain, linked, all acting** | **2.0 %** | none |
| the same, double buffers | 2.0 % | none |
| the same at 48 kHz | 1.0 % | none |
| 8 dynamic bands keyed by the input, unlinked | 3.3 % | none |
| 8 dynamic bands on a stereo sidechain, 64 channels (information) | 11.8 % | none |
| **8 dynamic bands unlinked, 64 channels (information)** | **150 %**, not real time | none |

- **Dynamic doubles the cost of a band.** Per band per sample: a float detector per key channel, a
  level, a target, the one-pole, and then, because the gain moves every sample, the band's
  coefficients every sample: an `exp2` for A (two for a shelf) and a divide for a1. The
  coefficients, not the detection, are most of it.
- **Unlinked multiplies the coefficients by the channels.** Each channel has its own gain, so each
  has its own coefficients, every sample. At 64 channels that is 1.5 cores in this scalar build.
  **For the author:** Phase 7's SIMD across channels is the planned remedy. Without it, Unlinked
  is for narrow layouts, and the PRD might say so.
- **The budget's case** (8 bands in Dynamic and Track, stereo sidechain, 96 kHz, 64 samples) is
  already at 2 % before Track, against the proposed 1 % (PRD, open decision, waiting for the
  author).
- **The static paths cost 8 to 12 % more than in Phase 2.** Two causes were found by elimination
  and removed:
  - MSVC had stopped inlining the band's per-sample coefficients into the chain's loop. The band
    now fills a stretch's coefficients itself.
  - Every band remade its detector's coefficients, an `exp` among them, at each moving step,
    whether a detector ran or not. They are now made on demand.

  What is left is each band's per-step bookkeeping (the gain computer's ramps, the shape).
- **The worst block is still Windows' scheduling,** on an ordinary thread (up to 337 % of a period
  once, on a run whose median was 2 %). The bench against the budget, Phase 7, runs at audio
  priority.

## Found on the way

- **A detector's first sample after silence reads nothing.** In the TPT form, v1² − v2·hp is
  exactly 0 at the first sample of a signal after silence, so the level there is −120 dB. A Below
  band therefore acts for an instant at a start, and is the input again once that has returned to
  zero, within 11 releases.
- **On a noise key the quadrature envelope dips to 0 for an instant.** The envelope of a narrow
  band of noise has deep troughs, and the cross terms take v1² − v2·hp under 0 where the max holds
  it at 0. An Above band does not mind: it acts a little less for that instant. A Below band acts,
  by hundredths of a dB at a 5 ms attack, and returns. So a Below band is not an exact bypass on
  broadband material even with the key over its threshold, only on a steady one. For the listening
  pass: whether that is heard, on an expander over a noisy room.
- **The fixed 256-sample chunk** costs nothing measurable and frees the shim from trusting a host's
  announced block size.
