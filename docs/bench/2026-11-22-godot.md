# Bench: Likyu in Go.dot, through its child

2026-11-22. The first time Likyu was measured as Go.dot plays a plugin: in Go.dot's plugin child,
through its shared region, under the allowance of Go.dot's namespace draft §139. The cases are
Go.dot's own (`tests/ProxyTests.cpp`: the smoke case, M35, M86, and a keyed case added for this
round), run on Likyu's VST3 at `32e3d5a` (0.1.0) in Release. Go.dot's side of the round is its
draft §142.

## How to run it again

Nothing enters the author's own Go.dot list: Likyu is scanned alone into a folder of its own.

```powershell
# Likyu's VST3 in Release, copied out of the build tree so it stays the one measured.
wfg plugins --engine-folder=<dir> --scan=vst3 --retry=<path>\Likyu.vst3   # prints the identifier
$env:WFG_ENGINE_FOLDER = "<dir>"
$env:WFG_REAL_VST3 = "VST3-Likyu-87f7ea5c-59639613"
$env:WFG_REAL_STATE = "<file>.state"        # M86: the real plugin's lanes in this state
$env:WFG_M86_CHANNELS = "2"                 # M86: the lane's width (default 2)
$env:WFG_M86_SECONDS = "3"
wfg_tests --test-case="M86*" --no-skip
$env:WFG_M35_PARAM = "1"                    # M35: the parameter the hand moves (Likyu's 0 is Bypass)
wfg_tests --test-case="M35*" --no-skip
$env:WFG_REAL_KEYED_STATE = "<file>.state"  # the keyed case: a state its sidechain turns down
wfg_tests --test-case="proxy: a real VST3's sidechain*" --no-skip
```

**A state file is the host's, not the plugin's.** A JUCE host keeps a VST3's state as
`copyXmlToBinary` of `<VST3PluginState><IComponent>`, the component's stream in JUCE's own
base64. Likyu's JSON, handed over as it is, is refused without a word: the first run of M86
measured an empty Likyu (18 µs a block) and Go.dot reported no problem. The states here were
written as the host keeps them, by a script that encodes the JSON that way.

The states:
- **M86, Likyu's `trackself`:** the bench's scenario of that name, eight bands in Dynamic and
  Track, keyed by Self (an M86 lane carries no key).
- **The keyed case:** band 1, a Dynamic bell at 2 kHz keyed by Sidechain, threshold −40 dB,
  range −12 dB.

## Figures (Windows, Core Ultra 7 255H, 48 kHz)

**Likyu's chain alone** (`likyu_bench time --scenario trackself --rate 48000 --block 512
--channels 2`): 132 µs a block at the median, 1.24 % of a core.

**M86, one lane, under the limit Go.dot ships** (three tenths of the block), in µs a block:

| Width, layout | Block | p50 | p99 | Misses | Beside 12 spinning children |
| --- | --- | --- | --- | --- | --- |
| 2, stereo | 512 | 168 | 465 | 0 | 2 misses, longest run 0 |
| 2, stereo | 128 | 45 | 183 | 0 | 2 misses, longest run 1 |
| 8, 8 in, 8 out | 512 | 216 | 522 | 0 | 1 miss |
| 8, 8 in, 8 out | 128 | 58 | 189 | 0 | 5 misses, longest run 2 |
| 16, 24 or 34 | — | 5 to 10 | — | 0 | the plugin lays out stereo; the cue passes dry |

Through the child, Likyu takes 36 µs more a block than its chain alone at stereo. That is about
the test gain's round trip (2 to 4 µs) plus JUCE's VST3 wrapper on both sides. It is not
separated further here.

Beside the twelve spinning children, the late blocks are the machine's, not Likyu's: the test
gain shows them in the same rows.

**Before and after Go.dot's fix** (§142, BHX): the same within run-to-run spread, as the fix
removes one allocation a block at 32 channels or more, which no VST3 lane reaches today.

**The arm's reset,** asked every half second beside a sounding lane: 10.9 ms at 512 samples and
5 to 6 ms at 128. The test gain shows the same (10.5, and 3 to 5): it is Go.dot's reset path,
whose 5 ms timer and one-block grain dominate, not Likyu's `reset()`.

**M35, a cue's state loaded onto a voice:** 8,319 bytes as Go.dot keeps them. The load takes
0.38 ms at least, 0.46 ms at the median and 1.38 ms at most. The other voice misses nothing,
loading or idle. The 288 parameters a load sets are no cost worth a remedy.

**The keyed case:** Likyu reports a stereo sidechain, which Go.dot's child lays out when the lane
is keyed and gives back when it is unkeyed. A 2 kHz tone at −26 dBFS reads −29.0 dB under a
silent key and −41.0 dB under a loud one: the band's range to a tenth of a dB, with no misses.

## Found

1. **Recall in Go.dot's order is exact.** At an arm the child calls `reset()`, then
   `setStateInformation()`, then sets every parameter again. `Chain::reset` already snaps at the
   next grid point, so a used instance and a fresh one with the same state play the same, bit
   for bit, and report the same latency. This holds with types, modes, a Track band, the band
   channels and the lookahead all changed. It is pinned now; it was not before. Without the
   reset the test fails at block 0.
2. **A sidechain laid out between blocks is heard as it is laid out.** Go.dot's `layKey`
   releases, sets one sidechain, stereo or mono, and prepares again at the same rate and width,
   so Likyu's `Chain::prepare` returns at once. The band hears the key, its fallback clears, and
   it falls back again when the key is taken away. Pinned in `ProcessorTests`.
3. **The silent-sidechain warning answered a fact that is gone.** Go.dot keeps the bus disabled
   until a key is picked, so Likyu falls back to Self and says so; once a key is picked the bus
   carries it. `hostFeedsSilence` and `Key::silentByHost` are removed (they were never shown),
   and the PRD amended.
4. **Wider than 8 channels, no VST3 is laid out wide in Go.dot.** JUCE's VST3 host cannot
   express a discrete set of more than one channel as a speaker arrangement, and
   `canonicalChannelSet` gives a discrete set past 8 channels. So Go.dot's ladder (`{w, w}`
   standard, then discrete) fails from 9 to 64 channels and falls to stereo, and the cue passes
   dry. REAPER reaches 64 channels by asking for 7th-order Ambisonics (Phase 1 bench). How
   Go.dot should ask is Go.dot's choice and its author's: put to him in §142, not changed.
5. **No units in Go.dot's catalogue**, by Likyu's design: the unit is in the value text
   ("20.0 Hz"), a Phase 1 finding, and Go.dot shows the text.
